# 常见问题

先记住三个万能命令：

```text
status     # 网络、配置、调度、上次结果
chain 0    # 全链路自检
logs 40    # 最近 40 行日志
```

99% 的问题看这三个就能定位。

---

## 使用与合规

**这算违规吗？**
自动化打卡可能不符合学校规定，风险由使用者自担。请先确认你所在学院/学校的相关要求，
并只在自己的账号上使用。

**会封号吗？**
设备每天只登录一次、只打卡一次，不做高频请求，并带随机抖动。
但平台随时可能调整规则或加强检测，本项目不能保证长期可用。

**需要一直开着电脑吗？**
不需要。只有蓝牙配置时需要电脑（或用安卓手机 + nRF Connect）。
配置完成后设备独立运行。

**能帮别人打卡吗？**
技术上支持多人账号表，但**必须每一位账号持有者知情并明确同意**，否则不要用。

**支持别的学校吗？**
不支持开箱即用。本项目按电子科技大学「晚安成电」平台实现，其他平台需要改源码。

## 刷机与硬件

**网页烧录工具里没有串口？**
换一根**能传数据**的 USB 线；装 CH340 / CP210x 驱动；换 USB 口。

**一直卡在 `Connecting....`？**
按住 **BOOT** → 点一下 **RESET** → 松开 BOOT → 重新 Connect。

**刷完蓝牙搜不到 / 串口打印 `invalid header magic`？**
刷错型号了。S3 和 WROOM-32 的固件不能混用，确认芯片丝印后重刷。

**刷完配置全没了？**
你刷的是 `-merged.bin`，它会清空 NVS。只想升级请刷 `-full.zip` 里的 `firmware.bin` 到 `0x10000`。

**板子反复重启 / 日志里有 `brownout`？**
供电不足。换 5 V ≥ 1 A 的电源和短一点的线，别接在电脑前置 USB 上。

**能用充电宝吗？**
可以，但要不间断供电；充电宝自动断电会让设备停机。

**能用 ESP32-C3 / ESP32-S3 的 8 MB 版本吗？**
C3 不行（源码未适配）。S3-N8R8/N8 没有 PSRAM 也能跑，只是余量小一些。

## 蓝牙与配置

**`--list` 搜不到设备？**
重新上电；关掉手机上占用它的 BLE App；确认板子没在别的电脑上连着；把板子靠近电脑。

**连接超时 / GATT 报错？**
Windows 设置 → 蓝牙 → 删除该设备后重连；或用 `tools/clear_ble_cache.ps1` 清缓存。

**WiFi 一直失败？**
只支持 **2.4 GHz**。先 `scan`，确认 SSID 的 `channel` 在 1–13；名字或密码含空格时改用
`raw {"op":"wifi.set","ssid":"我的 WiFi","pass":"a b#c"}`。

**怎么确认设备时间是对的？**
`time` 看是否为当前北京时间。WiFi 连上会自动校时，也可以 `time`（或 `raw {"op":"time.sync"}`）手动同步。

## 打卡相关

**`4001 登录无效或已过期`**
平台没有授权这次会话。多半是缺少「门户预热」这一步，或者指纹不对。
按顺序试：`login force` → `chain 0` → 看 `warmup` 和 `appEntry` 是否都是 `true`。

**`checkLogin` 302 回首页**
同上的原因：会话未被微应用授权。先确认 `chain 0` 里 `warmup:true`。

**`NEED_MFA`（需要短信验证码）**
这是 CAS 登录要求二次验证，通常与浏览器指纹未设置、错误或失效有关。用你**平时打卡的那台浏览器**重新取
`MULTIFACTOR_BROWSER_FINGERPRINT`，再 `auth` 重新写入。它与下方微信操作票据是两项不同的授权。

**打卡提示 `wx ticket failed`、`wx.import needed` 或微信换票失败**
平台要求打卡请求携带微信小程序操作票据。在 `ble_console.py` 中先执行 `wx status` 检查当前账号对应槽位，再用 `wx test 0` 测试（按实际槽位调整）。缺少凭据时，按[快速开始](quickstart.md#22-准备微信授权凭据)由账号本人扫码读取 Cookie 并用 `wx import` 导入；注意 `expires_in` 是剩余秒数，须换算为 Unix 到期时间 `expiresAt`，也可填 `0` 让固件先刷新。若刷新被拒绝，需重新扫码并导入；`chain` 不检查微信票据。

> 推荐使用 v0.6.0 固件与同版 APK。旧 v0.4.0 不支持微信票据；v0.5.1 支持票据，但可能截断较长的授权导入命令。

**桌面版打卡不成功？**
当前桌面版尚未实现微信票据流程；平台强制要求 `X-Checkin-Ticket` 后，桌面版不能完成新的打卡请求。该能力已在固件实现；Android 只负责控制开发板，不会为旧桌面版增加票据能力。

**`OUT_OF_WINDOW`**
不在 21:00–23:30 内。白天看到 `inWindow:false` 是正常的。

**返回成功但平台没记录？**
设备打卡后会自动复查，`status` 看 `last.ok`。如果复查返回 `pending`，
用 `probe` 再确认一次；仍然异常就 `logs` 看服务端原始响应。

**提示距离过大 / `distance` 很大？**
坐标不对或漂移了。人在宿舍重新取坐标（见 [快速开始](quickstart.md#3-取宿舍坐标)），再 `loc` 写入。

**白天 `chain` 一直 `session:false`？**
窗口外设备默认不登录，以保护会话。需要强制检查时用 `chain 0 force`。

**会不会重复打卡？**
不会。提交前会先查当天状态，已经打过就返回 `already checked in`。

## 通知相关

**通知发不出去？**
先 `http <你的推送地址>` 看设备本身能不能访问外网，再 `notify test 你好`。

**微信只收到标题、没有正文？**
Server酱正文键是 `desp`，升级到 0.3.1+ 即可自动适配。

**为什么一天只收到几条？**
重试通知每 3 轮才发 1 条，并且有 `gap`（默认 180 秒）和 `quota`（默认 20 条）限流。
调大或调小：`notify set url=… gap=60 quota=50`。

**通知失败会影响打卡吗？**
不会。通知失败只在日志里记一行。

**想把每个人的结果单独推给那个人？**
0.4.0 起支持多通道：`notify add wang url=https://sctapi.ftqq.com/<他的SendKey>.send style=2 accounts=A02`。
默认通道收全部事件与多人汇总；附加通道只收关联账号的逐账号结果。
详见 **[手机通知](notify.md)** 的「多通道分发」。

**桌面版和固件版的通知规则一样吗？**
一样。通道风格（0/1/2）、Server酱 `desp` 自动识别、按账号关联与「每人每天一条成功」的
去重，两边语义相同；桌面版用 `notify add/link/test` 命令或图形界面【推送】页配置。

## 其他

**设备日志里出现 `E NimBLEAttValue: val > max`？**
手机端一次发送的 JSON 太长（超过协商 MTU）。用电脑 `ble_console.py`，或把 JSON 拆小。

**串口提示 `psramKB: 0`？**
这块 S3 没有 PSRAM。固件会自动降级运行，功能不受影响，只是内存余量小。

**怎么彻底重置？**
`clear` 只清会话；`reset` 恢复出厂（输入 `YES` 确认），会清空 WiFi、账号表、坐标、通知、会话。
之后需要重新配置。

**升级会丢配置吗？**
刷 `firmware.bin` 到 `0x10000` 不会丢；刷 `-merged.bin` 会丢。

**OTA 升级？**
暂未实现，升级需要 USB 刷写。

**可以远程控制吗？**
不可以，设备只做定时打卡，没有远程控制接口。
