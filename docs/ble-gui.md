# 电脑蓝牙图形控制台

本工具通过电脑蓝牙控制 ESP32，复用 `ble_console.py` 协议；不依赖 Android APK，也不替代独立执行打卡的 `desktop/` 程序。

## 安装与双击启动

安装 Python 3.10+（Windows 安装器保留 Tcl/Tk 组件），在仓库根目录执行一次：

```powershell
python -m pip install -r tools/requirements-ble.txt
```

双击 [`tools/ble_console.pyw`](../tools/ble_console.pyw) 打开无终端窗口的 GUI。双击 [`tools/ble_console.py`](../tools/ble_console.py) 同样启动 GUI，但可能附带终端窗口。Windows 需要将 `.pyw` 关联到 Python；若没有反应或文件被编辑器打开，可右键“打开方式”选择对应环境的 `pythonw.exe`，勾选始终使用。终端中的 Python 与文件关联中的 Python 可能不同，请确保 bleak 安装在实际启动的环境中。也可执行：

```powershell
python tools/ble_console.py --gui
```

GUI 不自动安装依赖；缺少 bleak 时显示安装提示。Linux 需安装发行版的 tkinter、BlueZ，并具备蓝牙访问权限。macOS 需允许运行脚本的 Python/终端访问蓝牙。跨平台实机蓝牙兼容性仍待验证。

## 四栏目与使用流程

1. 扫描、选择并连接本人设备，保持扫描 / 连接 / 断开区域的使用方式。
2. **设备概览**以“项目 / 当前值 / 说明”表格展示原有运行信息；状态查询会刷新它。
3. **账号列表**依次显示序号、账号标签、完整学号、密码配置、浏览器指纹配置、微信授权、通知渠道、打卡启用、最近结果。序号从 0 开始。点击启用列或按空格切换，等待设备确认后生效。表格支持横向滚动。
4. **查询与配置**通过“分类 → 操作”两级菜单选择所有功能，上部表单独立滚动，下部固定显示友好结果。Wi-Fi 扫描显示全部 2.4 GHz 接入点，包括同名及隐藏网络，提供 SSID、RSSI、频道、加密和 BSSID。
5. **完整回执**只在开发者选项开启后出现；近期日志、原始 JSON 和会话工具也归入开发者菜单。帮助入口可离线阅读。

本工具随 0.8.0 正式发行。新账号管理需要固件 `hello.caps` 包含 `account-v2`，指定账号执行还需 `selected-execution`。请安装本版对应板型固件；旧发行版 0.7.0 没有这些能力。旧固件仍可查看原有状态，完整学号、安全合并、目标选择会提示升级，不以覆盖替代安全更新。

## 新建、修改与授权

“账号配置 → 添加或覆盖账号”中选择“新建账号”或“修改已有账号”。新建必须填写标签、学号、密码、32 位十六进制指纹。位置可选，采用设备保存的默认位置；文字地址不会换算坐标。

修改时按序号、标签或完整学号唯一匹配，输入框旁显示设备当前值或配置状态。**只提交非空字段，留空保留原密码、指纹、位置和启用状态**；经纬度成对修改，地址可独立修改。没有新输入不会发送。修改学号会清除该槽位微信授权和旧身份会话；仅改标签保留授权，并更新通知关联。若设备提示通知关联更新失败，请手动修正。

微信授权按序号或标签匹配目标；输入标签后自动读取设备账号表并定位槽位。匹配成功后扫码，可刷新二维码；授权只填入表单，仍需点击保存。账号快照变化会清除目标和授权输入，要求重新匹配。账号表为空时主账号对应槽位 0。删除或清空账号会先清除全部微信授权，避免顺序压缩后错配，保留账号须重新导入。

登录测试、全链路测试、立即打卡和多人演练可勾选一个或多个已启用账号。未选择不执行；禁用账号须先明确启用。设备逐账号隔离会话、票据与位置，汇总结果不会把其中一人的失败当作全部成功。全链路检查不提交打卡，立即打卡和取消演练中的“只体检”会真实提交。

## 隐私与操作提示

完整学号仅在当前账号快照界面显示；密码、指纹和微信令牌不回读。界面不保存到磁盘；敏感输入发送或切换操作后清空。设置从设备已返回的非敏感值填入，未提交输入不被刷新覆盖。

完整回执按敏感字段和已知敏感值脱敏，仅保留内存中约 500 行，关闭开发者选项或断线清空。自由文本不能保证识别所有个人信息，分享前仍需检查。

保存成功以设备同 ID 的成功回执为准。刷新失败会单独提示，不能推断保存失败。超时 / 断线表示结果未知，请查询后决定下一步，不自动重放。打卡、真实通知、登录、自动调度、删除和恢复出厂有确认提示。

连接失败先关闭其他 BLE 客户端、删除系统旧配对记录、开关蓝牙并靠近开发板；仍失败时可用 APK 交叉验证。

## 命令行兼容与验证

无参数运行现改为 GUI。原命令行使用 `--cli`，已有带参数命令保持不变：

```powershell
python tools/ble_console.py --cli
python tools/ble_console.py --list
python tools/ble_console.py --name WANAN-XXXX hello status
python -m unittest discover -s tools/tests -v
```

自动测试覆盖表单、能力协商、回执 / 断线语义、全部菜单渲染、账号匹配及源码包完整性；不访问真实设备或账号。2026-10-29 用户确认基本功能已查验无误，未提供逐设备或逐项流程明细。

从 [v0.8.0 Latest](https://github.com/richard297779/UESTC-MoonCheck/releases/tag/v0.8.0) 下载 `MoonCheck-0.8.0-ble-console-source.zip` 或整套发行 ZIP。旧 desktop-v1.1.0 中的 BLE 源码包保留为历史版本，不能提供本轮新界面。独立打卡桌面程序仍有自己的版本和验证范围。

## 内置微信扫码授权

在“微信授权”中选择“导入本人授权”，先匹配账号目标，再点击“微信扫码获取授权”。二维码可刷新；本人微信确认后，程序只把 OpenID、Access Token、Refresh Token 与 expiresAt=0 填回当前表单，仍需点击“执行 / 保存”。取消、切换表单或断开会停止扫码；旧二维码迟到结果不会填入新表单。扫码需要电脑联网，图片显示额外依赖 Pillow（包含在 tools/requirements-ble.txt）。

扫码使用独立的内存 HTTP 会话，不读取浏览器已有 Cookie，不持久化二维码、code 或令牌；仅访问指定微信/应用宝 HTTPS 地址。不提供账号权限判断或自动打卡。公共二维码与等待扫码轮询已通过网络验证；本轮用户已确认基本功能，但未给出逐项扫码闭环记录；失败时可手动导入。详见[实现与验证](../dev/docs/qr-authorization.md)。

扫码弹窗现按字体与缩放计算最小高度，并允许调整窗口大小，避免刷新 / 取消按钮被裁切。若 OAuth 在 302 响应中已经返回三个有效 Cookie，中控立即回填而不继续访问外部完成页；缺字段时不会绕过跳转限制，错误仅显示检测到的项数。修复后请关闭旧窗口、重新打开脚本并刷新二维码再试。

## 兼容说明

新版 GUI 使用 `account.snapshot` / `account.patch`。CLI 的 `account add` 和旧客户端仍使用历史整条覆盖协议；它们的留空语义与新版合并不同，修改已有账号建议使用新版图形界面。本版固件 / APK / BLE 源码统一为 0.8.0；升级时同步更新，不要混用旧界面与新协议。
