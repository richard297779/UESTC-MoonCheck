# 多人打卡

一块板子可以替**同宿舍的几个人**打卡。设备里有一张账号表，每个账号独立开关，
每晚会按顺序逐个执行。

> ⚠️ 使用前提：**每一位账号持有者都必须知情并明确同意**。
> 不要把别人的学号密码偷偷填进来——这既是账号安全问题，也可能违反校规。

---

## 添加账号

```text
account add A01 <学号> <密码> [指纹|-] [纬度 经度 [地址…]]
```

- 标签就是备注名，自己好认就行（`A01`、`小王`、`室友A`）。
- 指纹位置填 `-` 表示这个账号不单独设指纹（大多数情况建议**每个账号都填自己的指纹**）。
- 坐标可省略——省略就沿用设备当前坐标（`loc` 配的那个）。
- 地址可省略，也可写多个词。

示例：

```text
account add A01 2023XXXXXXX pass1 0123456789ABCDEF0123456789ABCDEF
account add A02 2023YYYYYYY pass2 0123456789ABCDEF0123456789ABCDEF
account add A03 2023ZZZZZZZ pass3 - 30.753500 103.934200 四川省成都市郫都区
```

> 每个人的指纹都不同，必须各用各的（指纹 = 那台浏览器）。填错会报 `NEED_MFA`。

---

## 查看与管理

| 命令 | 作用 |
| --- | --- |
| `account list` | 查看全部账号、开关状态、是否已配指纹 |
| `account on A01` | 启用 |
| `account off A01` | 暂停（保留配置，不参与打卡） |
| `account rm A01` | 删除 |
| `account clear` | 清空整张表 |

上限 **6 个**账号。设备里只保存明文，请勿转借。

---

## 每晚怎么执行

账号表非空时，设备按表顺序逐个执行「登录 → 门户预热 → 打卡 → 复查」。
账号之间默认间隔一段时间，避免同时请求。

```text
multi 30          # 设置账号间隔为 30 秒（0–600，默认见 status）
multi             # 立刻按账号表跑一轮
multi probe       # 只读演练：逐个登录体检，不提交打卡
multi force       # 跳过"今天已打过"的判断，强制跑一轮
multi probe force # 组合使用
```

`multi probe` 是最安全的验证方式：它会真的登录、真的做门户预热，
但**不会提交打卡**，用来确认每个人的账号都能正常授权。

跑完后用 `status` 看每个人的结果。

---

## 时间预算

每个账号要经历登录 + 门户预热 + 打卡 + 复查，大约 20–60 秒。
6 个账号加间隔，一轮大概 3–8 分钟。

打卡窗口是 21:00–23:30，时间非常充裕，**不需要把间隔压到 0**。
建议间隔 20–60 秒，减少被平台风控注意的可能。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 某个人一直失败，其他人正常 | 单独 `account off` 停用他，再用 `account add` 重新添加，重点检查指纹 |
| 报 `NEED_MFA` | 该账号的指纹不对或已失效，让他用自己浏览器重新取一次 |
| `account list` 里没有 | 检查标签拼写；`account add` 参数是否齐全（至少 5 段） |
| 想把主账号也加进表 | 可以。表非空后，`auth` 配的那个主账号**不再单独执行** |
| 全部报错 | 先 `chain 0` 确认设备本身链路正常，再排查指纹 |
| 忘记某人的密码 | 无法查看（设备只存不回显），删掉重新添加 |

---

## 安全建议

- 每个人只填自己的账号，密码让他自己输入，不要代填。
- 定期用 `account list` 核对，删除已经不需要的账号。
- 板子丢失或转手前，执行 `reset` 并输入 `YES` 擦除全部配置。
- `status` 与 `account list` 都会对学号打码、密码与指纹只显示「是否已设置」，可以放心截图。
