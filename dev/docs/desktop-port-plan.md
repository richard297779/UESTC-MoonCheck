# 桌面端 1.1.0 移植计划与验收

日期：2026-10-27。桌面版本独立从 1.0.0 升至 1.1.0；固件/Android 0.7.0 和已有发行不变。

## 目标与设计

复用桌面 CAS、账号、坐标、窗口、通知及 tkinter 界面，将本仓库 MIT 固件的微信 OAuth、MMTLS、ManualAuth、0-RTT js-login 和两次 code 换操作票据链路移植为 Python。上游 moon-uestc 虽为固件参考来源，但未提供明确许可证，不直接复制其 Python 源码；实现依据本仓库固件，协议公共常量保留来源说明。

新增 `wechat_wire.py`（加密/帧/protobuf/LZ4）、`wechat_transport.py`（有期限和长度上限的独立网络连接）、`wechat.py`（授权刷新与按账号取票）。AES-GCM/P-256 使用维护中的 PyCryptodome，不自行新增密码算法。保留原有纯 Python CAS AES。新增运行依赖、离线包依赖收集及第三方声明。

每个账号独立保存 openid/access/refresh/绝对到期时间。旧配置缺失新字段可正常加载，不能借用其他账号授权。刷新后立即原子保存旋转凭据；票据、小程序 code、MMTLS 密钥及会话仅内存使用，不写入配置。小程序 HTTP 客户端不共享 CAS Cookie。取票要两次独立 login_buffer/code：check-bind → 独立 MP SESSION → checkin-ticket；只将验证过的 43 字符票据附加到打卡 POST。

## 交付步骤

1. 移植编解码与网络：P-256、HKDF、AES-GCM、protobuf、LZ4、MMTLS 握手及 Finished 校验、PSK/0-RTT；用固件黄金向量和畸形输入验证。
2. 接入业务：授权导入/清除/状态/取票测试，过期或被拒时最多刷新重试一次；打卡前取票，46001/46002/46003 失效后不盲目重放提交，下一轮重取。
3. CLI/GUI：微信授权页可选账号、隐藏凭据、导入和测试；测试不提交。新增命令支持交互隐藏输入，不在进程参数中强制暴露凭据。
4. 桌面原有自动轮次继续由系统调度器调用 `auto`，不擅自安装系统定时任务；使用中国时区判断窗口，失败由下一轮重试，不改变多人通知语义。
5. 发布准备：桌面 1.1.0、示例配置、依赖及 PyInstaller 构建，更新使用/开发文档。默认不把未实测桌面二进制混入固件发行。

## 验收边界

离线验证：与固件黄金向量一致、GCM 篡改拒绝、截断帧/解压炸弹拒绝、socket 部分读写、凭据旋转落盘、账号隔离、两 code/独立 Cookie、缺授权不得提交、票据拒绝不重放、CLI/GUI 配置与脱敏、旧配置兼容及打包启动。

真实验收需用户本人提供授权，确认 CAS 登录、微信取票、真实提交与复查、跨日和通知。固件/Android 的实测结论不能沿用为桌面已实测。自动测试不使用真实账号、不提交打卡、不发送通知。最终执行结果另记桌面验证文档。
