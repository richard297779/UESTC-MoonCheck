# 蓝牙中控布局确认稿 V1

用户已确认本稿并授权实施。当前工作区已按此布局接入桌面 GUI，扩展固件协议并同步 Android 必要功能；纳入 0.8.0 发行。所有图示数据均为虚构，原型不请求网络、不连接蓝牙、不保存输入。

入口：[可交互界面原型](mockups/ble-console-redesign/index.html)。效果图与 HTML 位于同一目录，均可保留审阅。HTML 仅用于绘图和交互确认，不表示将桌面程序改为浏览器应用；现有 Python / Tk 启动方式可以保留。手机端需同步必要的协议及功能支持；此组效果图针对电脑窗口，不将九列表格直接挤入手机窄屏。

## 一、栏目与布局

| 栏目 | 内容 |
| --- | --- |
| 设备概览 | 将当前已有内容改为“项目 / 当前值 / 说明”表格：设备、固件、网络、IP、设备时间、自动打卡、计划、下次执行、最近结果、内存指标。状态查询成功后更新，同步显示读取时间。 |
| 账号列表 | 按用户指定顺序：序号、账号标签、完整学号、密码配置情况、浏览器指纹配置情况、微信授权情况、通知渠道配置、打卡是否启用、最近打卡结果。勾选启停直接操作，等设备回执后生效；失败恢复原值。 |
| 查询与配置 | 上部为“功能分类 → 具体操作”两级菜单与相应输入框；下部始终固定一个结果区。表单长时上部独立滚动，结果区不被顶走。所有操作共用同一结果区。 |
| 完整回执 | 仅开发者选项开启后出现。原始 JSON、协议事件和日志集中显示；敏感凭据仍隐藏，关闭或断线清空。 |

扫描 / 连接 / 断开区域保留现有设备选择、按钮顺序和帮助入口，只统一视觉样式。设备概览与账号表的刷新按钮是统一查询动作的快捷入口，不另外建立一套返回窗口。

账号表显示完整学号是本轮明确要求，仅用于本人设备的当前界面；密码、指纹、微信令牌仍只显示配置状态，不回读明文、不在日志中明文输出。通知列显示名称和启用情况，不显示 URL 密钥。表格过宽时提供横向滚动，不截掉尾列。

序号拟从 **0** 开始，直接对应微信槽位 0–5；页面显式提示。序号是当前快照中的位置，不作为长期身份，删改账号后需刷新重算。

## 二、多级菜单

| 一级分类 | 二级操作 |
| --- | --- |
| 状态查询 | 配置与运行状态、设备信息、设备时间、前置体检 |
| 网络 | 扫描 Wi-Fi、连接 Wi-Fi、校园网连通性、自定义 HTTP 测试、修改广播名 |
| 账号配置 | 添加或覆盖账号、启用或禁用账号、删除账号、清空账号列表 |
| 微信授权 | 授权状态、扫码 / 导入本人授权、测试取票 |
| 调度与执行 | 登录测试、全链路测试、立即打卡、多人演练、自动打卡开关、时间窗口、账号执行间隔 |
| 通知配置 | 通知状态、默认通道、附加通道增改 / 启停 / 删除、关联账号、测试通知 |
| 设备设置 | 单人基础账号、设备默认位置、恢复出厂 |
| 开发者工具（开启后） | 近期日志、Cookie 清理、SESSION 注入、原始 JSON |

切换操作时清理上一个操作的敏感输入；非敏感设置从设备读取，不把猜测值标为设备当前值。危险或真实联网操作保留确认，确认内容包含设备、账号范围和操作影响。

## 三、统一结果区

- **Wi-Fi 扫描**：表格显示全部接入点的序号、SSID、RSSI、频道、加密方式、BSSID；同 SSID 不同 BSSID 不去重，隐藏 SSID 仍保留一行。当前设备仅扫描 2.4 GHz，明确标注。列表长时在结果区内滚动。
- **查询**：按中文字段和状态表格展示，不把完整 JSON 当普通用户的主要结果。没有返回的值显示“设备未提供”，不伪造为 0 或未配置。
- **配置**：显示目标、已变更项、保留项与设备确认结果，避免仅显示“发送成功”。无新输入时提示“没有修改”，不发送请求。
- **执行**：逐账号显示操作、阶段、成功 / 失败 / 跳过 / 结果未知与时间。已完成与仍在进行的账号分开标记，超时不自动重放。
- **失败**：保留可理解的失败原因和下一步；不要因为刷新失败把已确认保存的配置显示成保存失败。

## 四、账号新增与留空保留

一个操作下区分“修改已有账号”和“新建账号”，避免用户不知道当前是合并还是新建。

### 修改已有

1. 可按序号、标签、完整学号查找，并从设备获取当前账号快照。
2. 显示已定位的序号、标签、学号；必须唯一匹配。重复学号或冲突条件不能擅自选择。
3. 所有新输入框默认留空。旁边说明设备当前值；密码和指纹只显示“已配置”，不回填秘密。
4. 仅提交有新输入的字段。空字段不发送，固件合并现有记录，保证密码、指纹、位置、启用状态等不被默认值覆盖。
5. 纬度和经度必须成对修改；地址可独立修改。保留独立位置输入，不能退回只有四个字段。
6. 没有任何新输入时不保存、不提交空补丁。清除字段如确有需求须独立显式动作，不能用留空暗示清空。
7. 修改学号属于身份变化，应明确要求重新授权并清理旧身份会话；仅改标签则维护通知关联，不把已有微信授权错配到别人。

### 新建

标签、学号、密码、浏览器指纹四项必填，指纹校验 32 位十六进制。经纬度 / 地址可选，未填写独立坐标时才使用设备默认位置。既有历史账号缺少指纹的情况可以展示为待补齐，不隐瞒其状态。

## 五、微信目标解析

支持通过序号或标签定位。通过标签时，“自动扫描”按 **自动读取 / 刷新当前设备的账号表，再查找标签对应序号** 实现，不重新扫描或切换 BLE 设备。

匹配成功显示“标签 → 序号 / 微信槽位 → 学号”，扫码只填表，不自动发送。保存前再校验快照，期间若有删除 / 重排 / 身份变更则中止，要求重新确认；不能把旧序号的授权导给新账号。标签不存在或不唯一时禁用保存。账号表为空的单人模式明确显示“主账号 / 槽位 0”。

## 六、指定一个或多个账号执行

登录测试、全链路测试、立即打卡、多人演练提供目标多选，支持全选已启用账号与单独勾选。未选择目标时不执行。默认不偷偷启用被禁用账号；若要执行该账号，先在账号表中明确启用。

执行确认显示本次操作及完整目标名单，不再使用当前全局账号作为隐式目标。设备按选择的顺序串行处理，每个账号使用自己的凭据、微信槽位、会话与位置，结果也按账号归属返回。不能通过临时关闭未选中账号来模拟选择范围，不能把 A 的 Cookie / 票据用于 B。强制模式默认关闭且不改变窗口、已打卡等检查的已有语义。

## 七、现有能力与固件适配

| 需求 | 当前源码实际 | 确认后拟实施 |
| --- | --- | --- |
| 全部 Wi-Fi 记录 | `WifiManager::scan()` 已逐条返回 SSID / RSSI / channel / enc / BSSID | 客户端完整渲染，不按 SSID 去重；同时核对 SSID 的 JSON 转义；必要时补扫描分页和长度边界，不截断回执。 |
| 完整学号 | `AccountStore::toJsonSummary()` 当前直接打码，客户端拿不到完整值 | 增加明确的账号详情读取能力，普通界面使用完整身份；旧摘要和诊断日志保持脱敏。不得靠猜测恢复学号。 |
| 留空保留 | `handleAccountAdd()` 当前新建整条 profile，缺失坐标回退全局值，不能实现字段合并 | 新增账号补丁 / 合并路径：先读取原记录，仅应用显式非空字段，原子保存；创建与更新分别校验。 |
| 多种账号查找 | 当前大多仅按标签；序号 / 学号匹配不完整 | 客户端统一账号解析器，设备再次校验目标与快照修订号，冲突失败。 |
| 微信按标签自动定位 | 当前 `wx.import` 接受 slot | 保留 slot 协议并加目标一致性校验；保存前复查标签、身份与当前 slot，拒绝旧映射。 |
| 指定账号执行 | `workTestLogin()` 使用当前服务账号，`workMultiCheckin()` 调用 runAll，无子集过滤 | 扩展选择目标的执行请求与队列载荷；按账号创建 / 还原执行上下文，逐人返回进度，不持久修改全局启用开关。 |
| 表格直接启停 | 已有 `account.enable` 与设备回执 | 可复用，增加等待态、失败恢复及刷新。 |
| 通知配置汇总 | `notify.status` 已提供默认通道、附加标签与 accounts 映射 | 按默认通道、all 和显式账号关联合并展示，区分启用 / 停用，不泄露 URL。 |

接口名称与具体字段将在实施时统一设计；本稿中的 account.patch 等为设计示例，不表示当前已实现。对旧固件能力不足必须显示需升级，不能用“覆盖整条账号”冒充安全的合并更新。账号快照 / 修订校验、删除导致槽位改变、标签重命名的通知映射与身份更换的授权清理需要一并处理。

实施时保持 ArduinoJson 嵌套序列化正确、BLE 分片 / 串行写入 / 回执语义和队列内存所有权。若改固件共用代码，按工程指南构建六目标并校验元数据；新增四种目标仍未实机验证。Android / Python 都需识别新能力，不能只改电脑界面而让手机仍覆盖丢字段。
